# Shred v0.1 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Shred v0.1 as a local single-user PWA that turns informal Chinese activity messages into editable, time-resolved, automatically categorized atomic events.

**Architecture:** A React/Vite PWA calls a same-origin FastAPI application. FastAPI persists source text before synchronously invoking an OpenAI-compatible classifier, validates the structured result, and commits events, taxonomy changes, tags, and lightweight correction memory to SQLite. A multi-stage Docker image serves both API and compiled frontend from one container.

**Tech Stack:** Python 3.12, FastAPI 0.139.2, Pydantic 2, SQLAlchemy 2.0.51, Alembic 1.18.5, OpenAI Python 2.x, React 19.2.8, TypeScript, Vite 8.1.5, TanStack Query 5, Vitest, Playwright, SQLite, Docker Compose

## Global Constraints

- Governing specification: `docs/superpowers/specs/2026-08-10-shred-mvp-design.md`.
- Preserve every submitted source message exactly; classification failure must never discard it.
- One deployment has one private user. Do not add registration, login, sessions, tenant IDs, or cloud synchronization.
- Start with an empty taxonomy. Categories have at most two levels, one category path per event, and at most three Agent-generated tags.
- Prefer existing categories before creating new ones; stable categories describe reusable areas or activity types, while one-off names belong in tags.
- Store SQLite at `/data/shred.db`; default Docker publishing is loopback-only.
- Read the API key only from `SHRED_OPENAI_API_KEY`; never return it, log it, export it, or place a real value in `.env.example`.
- Keep the frontend and API same-origin in production; do not enable permissive CORS.
- UI copy is Simplified Chinese. Source code identifiers and technical documentation are English.
- Use synchronous SQLAlchemy sessions and synchronous OpenAI calls; FastAPI `def` endpoints provide thread-pool isolation without a queue or worker.
- Use UTC for persisted timestamps plus the source IANA time zone and occurrence precision needed for natural display.
- Run commands from `D:\WorkSpace\Code\Project100\Shred`. On this sandbox, prefix Git commands with `git -c safe.directory=D:/WorkSpace/Code/Project100/Shred` and do not alter global Git configuration.
- Never claim real-model acceptance unless a locally supplied key was used. Mocked tests, Docker checks, and live-model checks are separate evidence.

class CorrectionContext(BaseModel):

- [ ] **Step 3: Implement taxonomy transactions**

Implement a service constructed as `TaxonomyService(session: Session)` with these signatures:

```python
def tree(self) -> list[CategoryNode]: ...
def create(self, command: CategoryCreate) -> CategoryView: ...
def rename(self, category_id: str, command: CategoryRename) -> CategoryView: ...
def merge(self, source_id: str, target_id: str) -> MergeResult: ...
def impact(self, category_id: str) -> DeleteImpact: ...
def delete(self, category_id: str) -> DeleteImpact: ...
def resolve_choice(
    self, choice: CategoryChoice, *, origin_message_id: str
) -> Category: ...
```

`CategoryCreate` contains `name` and optional `parent_id`; `CategoryRename` contains `name`; `CategoryNode` contains the category view, direct/total event counts, and recursive `children`; `DeleteImpact` contains category, descendant, and affected-event counts. Service methods may `flush()` but never commit, so a message-classification transaction can create categories and events atomically. The taxonomy router wraps each standalone mutation in `with session.begin()`. `merge(source_id, target_id)` must reject identical IDs and different depths. `impact(category_id)` returns counts without mutation; `delete(category_id)` performs the counted mutation inside the router-owned transaction.

```text

POST   /api/categories
PATCH  /api/categories/{category_id}
POST   /api/categories/merge
POST   /api/categories/{category_id}/delete-impact
DELETE /api/categories/{category_id}
```

Use error responses shaped as `{"error": {"code": str, "message": str}}` and map name conflicts to HTTP 409, invalid depth/merge to 422, and missing categories to 404.
